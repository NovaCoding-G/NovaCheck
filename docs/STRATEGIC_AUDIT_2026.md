## Executive Verdict

**No — non investirei $500.000 nello stato attuale.**

NovaCheck è un **CLI open-source competente, prematuro e mal posizionato**: qualità tecnica sopra la media per un founder di 18 anni, ma prodotto ancora **commodity + packaging**, traction quasi nulla (**2 stelle GitHub**, **~260 download npm** nell’ultima settimana = mese, **0 issue aperti**, rilasci da ~6 giorni sul registry), e un mercato già invaso da unicorni (Socket, Aikido, Semgrep, Obsidian) e da una nuova ondata di clone “AI code security” (ZenVeil, Erzo, VibeSafe, Plexicus, slopcheck).

**La buona notizia:** nel codice c’è un seme reale — `ghost-deps` (hallucinated / slopsquatting packages) + gate CI locale + fix prompt copy-paste. Quello è l’unico asse non-commodity.

**La cattiva:** Trust Score, secrets, sinks AST, supply-chain shallow e AI-provenance (quasi sempre skipped) **non bastano** a costruire una company. Il marketing parla di “trust layer for AI-generated code”; il prodotto è un **SAST leggero con un detector interessante**.

**Decisione strategica:** **continuare, ma con pivot di posizionamento e narrowing drastico** — non diventare AppSec platform; diventare **il gate di trust pre-ship per chi costruisce con agent AI**, con wedge su **ghost packages + policy CI + report condivisibili**, open-core.

Legenda evidenza usata sotto:
- **FACT** = osservato nel repo / fonti primarie
- **ESTIMATE** = stima quantitativa ragionevole
- **ASSUMPTION** = ipotesi operativa
- **INFERENCE** = conclusione analitica

## 1. Current Product Reality

### Cosa fa davvero (FACT)

`npx novacheck .` esegue 8 detector in sequenza (`src/detectors/index.ts`), calcola un Trust Score 0–100, stampa report terminale, scrive HTML (default `.novacheck/report.html`), opzionalmente SARIF/badge, applica policy `.novacheck.yml`, supporta `--changed`, `--offline`, `--fail-below`, GitHub Action (`action.yml` → `npm exec novacheck@0.4.0`).

| Detector | Natura reale |
|---|---|
| `ghost-deps` | Registry lookup npm/PyPI + typosquat Levenshtein + age/downloads + risoluzione alias/workspace | **unico pezzo differenziante** |
| `secrets` | Wrapper `@secretlint` + entropy | **commodity** |
| `env-leak` | `.env` non protetto / tracked in git | **utile, piccolo** |
| `supply-chain` | Solo `package.json` lifecycle scripts pericolosi + `git+http://` | **shallow commodity** |
| `dangerous-sinks` | Tree-sitter pattern match (shell/SQL/CORS/TLS/eval/XSS/deser) JS/TS/Python | **SAST toy, non taint analysis** |
| `insecure-crypto` | Pattern crypto debole | **commodity** |
| `ai-unreviewed` | Solo se esistono Agent Trace / SPDX-AI-Disclosure | **quasi sempre skipped in natura** |
| `ai-presence` | Marker espliciti (`Generated by Cursor`, trailers, AI_DISCLOSURE) | **info only, non abbassa score** |

### Cosa afferma di fare (FACT — README)

> “Run this before shipping AI-generated code.”  
> “local-first security and AI-provenance scanner”  
> “0–100 Trust Score, prioritized findings, copy-paste fix prompts, HTML, SARIF”

### Cosa **non** fa (FACT)

- Nessuna analisi CVE / advisory database (esplicitamente droppata)
- Nessun taint tracking / dataflow
- Nessuna copertura Go/Java/Rust/C#/Ruby
- Nessun IDE plugin / MCP / hook agent runtime
- Nessun blocco install-time (a differenza di Aikido Safe Chain / Socket Firewall)
- Nessuna SaaS, dashboard, auth, multi-repo, team policy cloud
- Nessuna generazione di patch automatica (solo **prompt statici**)
- Nessuna prova di “AI-ness” senza provenance esplicita (scelta corretta, ma riduce coverage)

### Remediaton: ispezione (FACT)

Ogni `Finding` ha `fixPrompt: string` (`src/types/finding.ts`). I prompt sono **template statici** scritti a mano nei detector (es. shell.ts: “Remove interpolation… use spawn/execFile…”). Il terminale e l’HTML espongono “Copy prompt”.

**Verdetto remediation:** **sufficiente come DX di loop AI**, **insufficiente come differenziatore commerciale**. Semgrep/Snyk/GitHub Copilot Autofix (agentic autofix luglio 2026) sono già oltre. Non aggiungere “AI chatbot” o “auto-fix LLM” come feature core — sarebbe rincorsa persa. Il valore attuale è **accelerare il paste in Cursor**, non sostituire un agent fix.

## 2. Technical Audit

### Architettura

- **Linguaggio:** TypeScript ESM, runtime publish Node ≥20, dev Bun 1.3.14  
- **LOC `src/`:** ~7.900 (**FACT**)  
- **Dipendenze runtime:** secretlint, web-tree-sitter + grammars JS/TS/Python, yaml  
- **Pipeline:** `createScanContext` → detector sequenziali → `computeTrustScore` → reporters  
- **Estensibilità:** interfaccia `Detector` pulita; lista hard-coded  
- **CI:** `ci.yml`, `novacheck.yml`, `release.yml` con pin commit immutabili — maturo per età  
- **Test:** fixtures per detector + golden known-bad + product-features + reporters (~2.3k LOC test)

### Bottleneck che impediscono lo scaling

1. **Detector sequenziali, full-tree walk** — performance degrada su monorepo grandi.  
2. **Niente dataflow** — sinks generano FP/FN strutturali vs Semgrep/CodeQL.  
3. **ghost-deps dipende da registry HTTP** — rate limit, incomplete scan; buona la diagnostics/`failOnIncomplete`, ma UX fragile.  
4. **Provenance AI** dipende da formati quasi non usati → feature “AI” spesso no-op.  
5. **Solo JS/TS/Python** — mercato agent AI è multi-language.  
6. **MIT + tutto open** — nessun pezzo proprietario su cui monetizzare.

### Qualità codice — score tecnico: **7.0 / 10**

Motivi del 7:
- Tipizzazione chiara, policy, diagnostics incomplete, pin actions, smoke CLI/pack, precision ethos in CONTRIBUTING (**positivo**).
- Sinks senza taint, supply-chain ridicolo rispetto a Socket, Trust Score non calibrato empiricamente, ai-unreviewed inoperante in produzione, zero benchmark pubblici di precision/recall (**negativo**).

**False positive risk:** medio-alto su sinks (pattern match) e “very-new package”; basso-medio su nonexistent packages.  
**False negative risk:** alto su vulnerabilità semantiche, malware in package esistenti, languages non supportati, agent install-time.

**Sicurezza di NovaCheck stesso:** design local-first sensato; rischio tipico di tool che eseguono parse su repo untrusted (DoS via AST enormi) — non mitigato in modo evidente.

## 14. Customer Acquisition

### ICP iniziale (UNO solo)

**AI-native startups e indie hackers (1–10 developer) che shippano settimanalmente con Cursor/Claude/Copilot Agent, senza security engineer.**

- **Workflow:** prompt → accept diff → push → Vercel

- **Obiezioni:** “Semgrep already”, “too many tools”, “false positives”, “who are you?”  
- **WTP:** €19–49/mo se il gate è silenzioso e catcha 1 ghost reale

### First 10 paying customers — playbook esatto

1. **Target:** founder che postano “built with Cursor/Claude” su HN/IH/X + YC AI batch public Launch HN.  
2. **Dove:** reply utili (non spam) + DM Indie Hackers + 30 outreach/settimana email “I scanned your public repo — found N ghost/secret risks”.

4. **Offrire:** setup Action in 15 min fatto da te; report settimanale.  
5. **Non dire:** “AI-native AppSec platform”, “Trust Score rivoluzionario”, “meglio di Snyk”.  
6. **Onboarding:** 1 repo, threshold 85, fail on critical, ignore tests.  
7. **Feedback:** call 20 min dopo 7 giorni; chiedere quali finding ignorati.  
8. **Prezzo first 10:** €19/mo o €49/mo con sconto founder 50% × 3 mesi.

## 22. Final Decision
